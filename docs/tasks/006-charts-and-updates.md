# 006：用量图表与版本更新检查

## 目标

在当前 macOS 提醒版范围内增加两项能力：

1. 用原有接口总量和应用归因快照展示可读的图表。
2. 检查公开正式版本，提示新版本并打开下载页；当前不自动替换应用。

## 范围

### 图表

- 使用 macOS 原生 Swift Charts，不引入第三方 UI 或网络依赖。
- 在用量详情页展示：
  - 接口上传／下载对比；
  - 应用归因排行；
  - 当前接口每日预警阈值（若已配置）的进度。
- 图表数据直接来自当前 `AgentSnapshot`，不新增 SQLite 表，不保存采样流水。
- 应用归因图表必须明确标注“仅用于分析”，不得把应用合计画成接口总量的百分比，也不得用接口总量减应用合计推导未知来源。
- 数据不可用、过期或跨日时显示未知状态，不显示成零用量。

### 版本检查

- 从应用 Bundle 读取当前 `CFBundleShortVersionString` 和 `CFBundleVersion`。
- 通过 HTTPS 请求 GitHub 正式 release 信息，过滤草稿和预发布版本。
- 在设置页显示当前版本、上次检查结果、发现的新版本，并提供“检查更新”按钮。
- 新版本通过系统浏览器打开 release 页面；不自动下载、替换或重启应用。
- 请求失败、响应格式错误、无正式 release 时显示可理解的错误或状态。
- 网络请求放在主应用的独立服务中，不进入采样 Agent、Core 计量和 SQLite 写入链路。

## 非目标

- 本轮不实现历史趋势图、按小时／分钟聚合持久化和导出。
- 本轮不实现 Sparkle 自动安装。
- 本轮不建立签名、公证或正式发布流水线。
- 本轮不改变 nettop 采样、接口总量、应用归因、额度或预警语义。

## 验收标准

- 用量详情页在接口数据有效时显示上传／下载图表；应用存在时显示归因排行。
- 数据无效时图表不会伪造为 0；图表文字和辅助功能描述包含单位和统计口径。
- 版本比较可以识别同版本不同 build、新版本、旧版本和非法版本。
- 更新检查能处理 HTTP 错误、网络失败、缺少 release、草稿／预发布和不完整 JSON。
- 设置页可手动触发检查，并显示检查结果。
- Swift 单元测试、macOS 构建和现有回归检查通过。

## 实施切片

1. 提取图表展示数据并实现 `UsageChartsView`，接入 `UsageDetailsView`。
2. 实现版本元数据、GitHub release 解码、版本比较和 `UpdateChecker`。
3. 接入设置页状态与按钮，补充测试和文档。
4. 完成自检、测试、构建，并记录当前未覆盖的正式发布限制。

## 后续事项

如果需要“今日趋势折线图”，另行设计当天有限聚合桶和 schema 迁移；不能把当前快照重复绘制成历史数据。
