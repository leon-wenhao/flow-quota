# 005 本机流量统计与阈值提醒

范围更新：2026-11-05 在 nettop 应用归因和高成本自动计量之外加入独立物理接口总量；仍不自动阻断。原 NetworkExtension 阻断任务保留为未来独立阶段。

## 实现口径

- macOS 14+ 原生 SwiftUI、用户会话 Agent、SQLite；不安装过滤扩展，不修改 SIP，不使用私有 NetworkStatistics 框架。
- 按本机 `man nettop` 使用 `-P -L 0 -s 2 -n -x -t external -J bytes_in,bytes_out`，单个长生命周期子进程。使用 SDK `openpty` 提供本地伪终端，避免 nettop 在无限管道模式下全缓冲；CSV 本身仍按官方 `-L` 模式输出，不经过 shell。默认包含 TCP/UDP，external 排除 loopback，但不等于运营商公网计费范围。
- CSV 重复表头划分完整样本，收到下一表头才发布上一帧，因此有约一个采样周期的发布延迟。输出、帧行数、异步队列均有上限。格式变化、超界或进程退出显式失败，不返回假零。
- libproc 的 proc_pidinfo(PROC_PIDTBSDINFO) 获取进程启动时刻，proc_pidpath 获取路径，查询前后校验出生标识；路径归并最外层 .app 的辅助进程，独立命令和系统服务按执行文件路径列出。仅为路径归属，不等于代码签名身份或业务请求来源保证。
- 首次观察、PID 重用、计数下降、样本丢弃、超过 8 秒的间隔、切网、手动标记变化及跨日，都重建基线。服务只累计连续观测区间，不回填未知流量。已有进程首次发现时的累积计数不计入当天；只有 SDK 出生时刻能证明在连续观测区间内新启动的进程，才可计入首批计数。
- 网络契约：可用（`NWPath.status == .satisfied`）且 `isExpensive` 的连接为 `.expensive`，自动计量；`.hotspot` 仅表示用户明确手动标记；`.ordinary` 不自动计量，`.unknown` 表示网络状态不可用。高成本不等于已确认手机热点。两种计量状态共用同一应用、当前日用量与提醒预算，切换不清零、不另发额度。网络更新清除手动标记并重新判断。多网卡同时活动时，nettop external 进程合计不能保证只来自选定路径。
- 应用采样批次事务失败时停止该采样源；独立接口任务按自己的状态继续。接口事务失败则重建基线，不重放可能已提交的增量。schema v3 增加独立按日接口实体，应用账本保留，旧应用合计不回填。运行期基线不持久化，重启未知区间不补算。

## 通知与生命周期

Agent 根据已持久化用量提出接近阈值/达到阈值事件。主应用每 5 秒刷新，即使菜单关闭也继续调度；必须保持主应用运行。UserNotifications 获得授权并接受请求后，客户端才 ACK Agent 记录去重。按应用、日期、规则版本、事件种类去重；调低阈值后可以产生新版本事件。达到阈值不阻断连接。

拒绝权限、调度失败、ACK 失败可见；未调度成功不写“已通知”。确定性请求 ID 降低重试影响，但调度成功到落库间崩溃仍可能重试，不能保证恰好一次横幅。系统专注模式等可影响送达与展示。

退出先停止采集并等待任务完成；服务无法确认时，允许用户明确选择仅退出界面，此时采集状态未知且不再投递通知。再次点击启用采集可恢复。采集由后台服务承担，停止期间流量未知。登录项与后台服务系统批准、通知批准/拒绝需对应用户环境验证。

## 边界

- 不承诺捕获首帧前或两帧之间已经退出的短生命周期进程的全部流量。
- 应用多进程归并、代理/TUN、共享系统进程、TCP/UDP 计数刷新与源移除行为需要具体环境验证；计数下降会放弃未知区间。
- 不把所有应用合计当作物理接口计费流量；代理可能造成归属歧义和重复。界面保留说明。
- 本机通过采样不等于所有 macOS 版本都已验证；最低系统与 Intel 真机仍需验收。

验证结果见 ../implementation-status.md。
