## 当前提醒版网络范围（2026-11-05）

本轮只交付 macOS 采样与阈值提醒，不自动阻断。网络识别与每日预算采用以下契约：

| NetworkState | 含义与计量 | 手动入口 |
| --- | --- | --- |
| `.expensive` | `NWPath.status == .satisfied` 且 `isExpensive`；自动累计观测增量 | 隐藏重复标记按钮 |
| `.hotspot` | 用户明确手动标记当前连接；累计观测增量 | 可取消标记 |
| `.ordinary` | 普通可用路径，归入普通网络类独立累计，提醒默认关闭 | 可手动修正为热点分类 |
| `.unknown` | 网络状态不可用，不分配新增量 | 网络可用后才能标记 |

高成本网络不等于已确认手机热点、设备或运营商。`.expensive` 与 `.hotspot` 的上传＋下载共用同一应用、当前日用量与提醒预算，切网或切换标记不会清零或另发额度。schema v5 将两类的应用规则／当日累计、独立接口总量及提醒状态按类别隔离；普通网络不参与热点类阈值。首次采样、重启、跨日、切网和采样间断重建基线，不回填未知区间。

主面板可切换“热点／高成本”和“普通网络”，并将实际网络归类与应用采集、接口计量状态分开呈现，避免暂停或接口不可用时宣称正在计量。手动热点属于低频分类修正，入口位于“通用设置 → 网络分类修正”的默认收起项；菜单栏概览仅显示当前网络状态。开关继续以服务确认为准，手动标记仍可取消，系统已识别高成本网络时隐藏重复开关。汇总与菜单栏使用“今日计量接口总量”，数据来自独立物理接口观测；应用列表使用“应用用量分析（可能重叠）”，不再用应用合计填充顶部。接口总量仍不等于运营商账单。保存规则只确认提醒配置持久化；达到阈值仅通知。

官方行为依据为 Apple `NWPath.isExpensive`（https://developer.apple.com/documentation/network/nwpath/isexpensive）；采用成本信号自动计量是本项目策略，不将该 API 解释为手机热点身份认证。适用最低 macOS 14、Swift tools 6.0；本次集成验证由主任务统一记录。

## 原始 V1 目标（历史设计与未来阶段）

以下第 1–10 节保留原始双平台保护设计；涉及热点范围、阻断与扩展的描述不作为当前提醒版行为，当前范围以上述契约为准。

## 1. 目标与范围

Flow Quota 是面向 macOS 和 Windows 的本地应用流量监测与每日额度管理工具，产品定位不限定于热点。第一版仅支持热点场景；后续版本可扩展到普通 Wi-Fi 及其他网络，扩展功能不属于第一版交付范围。网络识别、适用网络范围与额度规则应保持独立，便于后续扩展。

仅在连接热点、或用户明确将当前连接标记为热点时，监测各应用及系统后台进程的流量，按应用执行每日额度、接近额度提醒和超额阻断。所有规则、用量、通知状态均留在本机。

产品是可安装的桌面应用：macOS 入口是顶部菜单栏，Windows 入口是任务栏通知区域（系统托盘）。关闭弹出面板不影响保护服务。第一版不包含历史报表、导出、限速、域名规则、账户、云同步、遥测、广告或自动更新检查。

建议的首发支持范围：

| 平台 | 首发目标 | 安装包 |
| --- | --- | --- |
| macOS | macOS 14 及以上；Apple silicon arm64 与 Intel x86_64 都作为发布验收对象 | `.dmg`，内含 `.app`；优先 Universal 2，通过全部组件构建验证后发布，否则按架构分别发包 |
| Windows | Windows 11 x64 | `.exe` 离线安装器，内含应用、后台服务与已签名驱动；内部使用 `.msi` 管理应用／服务安装 |

Windows ARM64、Windows 10 不列入默认首发支持清单；需要时另行验证并扩展。以上是本项目支持范围选择，不代表相关 API 的最低系统要求。两端必须使用相同的产品规则与状态语义，但网络引擎与界面分别原生实现。

## 2. 菜单栏／系统托盘与界面

### 2.1 常驻入口（macOS 菜单栏／Windows 系统托盘）

- macOS 原生状态项默认显示单色盾牌图标和「今日热点用量」，例如「1.19 GB」。文字可在设置中隐藏。
- Windows 使用系统托盘图标，悬停提示今日用量和保护状态；点击打开相同信息结构的面板。Windows 首发不承诺在标准托盘图标旁常驻任意用量文字；系统可能将图标收进溢出区域，提供本地操作说明。
- 使用单色符号变化和可访问名称区分：普通网络、保护中、接近上限、已有应用被阻断、保护异常。不能仅靠颜色区分状态。
- 点击展开约 420 pt 宽的原生面板，点击外部收起。小屏幕不超过可用宽度；长应用列表使用原生滚动。
- macOS 采用 MenuBarExtra 的 window 样式；LSUIElement = true，默认不出现在 Dock 和应用切换器中。
- Windows 采用 WPF 面板与 Windows Forms NotifyIcon 托盘入口，默认不为收起的面板保留任务栏按钮；支持系统缩放、键盘操作及多显示器边缘定位。

### 2.2 主面板

1. 顶部：当前连接类型、热点识别状态及手动标记入口。不依赖取得 SSID 才能工作。
2. 汇总：今日所有已归因应用的热点流量合计。代理场景不得把原应用与代理转发的同一份数据重复相加。
3. 应用列表：图标、名称、今日上传＋下载总量、每日上限、用量进度、保护状态。不限额的应用仍可监测。
4. 默认按今日用量降序；需要提醒、已阻断和保护异常状态清楚可见。第一版不增加独立排序、筛选或报表工具。
5. 底部：本地保存说明与设置入口。

列表覆盖 macOS 壁纸下载、Windows 更新相关后台服务等；可靠识别的辅助进程合并到所属应用，无法可靠归属的共享服务单独显示，不猜测原应用。Windows 的共享宿主（如 svchost.exe）只有在可靠识别服务身份后才分组，不能把阻断整个宿主宣传为精准控制单项服务。未能计量或归因的流量不能悄悄记为零，须显示覆盖限制。

### 2.3 应用额度编辑

点击应用，在同一面板进入编辑页：

- 显示今日已用量；上传和下载均计入。
- 开关「每日流量上限」。未设置时默认不限额，并明确显示。
- 数值输入＋MB/GB 单位，按十进制存储：1 MB = 1,000,000 bytes，1 GB = 1,000,000,000 bytes。
- 提醒阈值可设置为 1%–99%，默认 80%。
- 保存后立即执行；调低到已用量以下则阻断，调高至高于已用量则允许后续重连。
- 不提供「清空今日用量」或「临时不限额」入口，避免绕过每日额度。
- 仅在保护服务确认接收新规则后显示保存成功。失败时保留旧规则并给出本地错误信息。

### 2.4 必要设置与首次启动

设置仅包含：开机启动、macOS 菜单栏用量文字、当前连接的热点标记，以及保护组件／通知状态。Windows 显示服务与驱动状态，macOS 显示系统扩展与过滤配置状态。

首次启动按顺序展示：本地处理说明 → 启用保护组件 → 配置本地通知 → 开机启动选项。macOS 需要完成系统扩展与过滤授权；Windows 安装器通过 UAC 安装服务和驱动，平时托盘界面以普通用户权限运行。拒绝通知不影响计量和阻断；保护组件未正常运行时不能显示「保护中」。

「退出并停止保护」应先停用过滤规则并确认结果，再退出界面、停止本用户会话的保护；不会留下用户无法发现的阻断。Windows 服务的安装状态与用户会话的保护状态分开管理。仅收起面板不退出服务。

## 3. 用量与每日规则

| 项目 | V1 行为 |
| --- | --- |
| 统计范围 | 热点下的应用上传＋下载；普通网络不消耗热点额度 |
| 当天累计 | 同一天多个热点、多次断开重连累计；不按热点分别发放额度 |
| 每日重置 | 本地时区自然日 00:00；休眠后首次处理事件时补执行跨日切换 |
| 已有连接 | 连接跨日／切网后，按新日期与网络状态处理后续数据，不将整条连接归入开始时的日期 |
| 重启恢复 | 当天用量、规则、提醒状态、超额状态持久化，重启不重置 |
| 预警 | 首次跨过自定阈值通知一次；本地保存日期＋应用＋阈值版本的去重状态 |
| 超额 | 阻断现有受控流后续数据与新连接；通知一次并在面板显示原因 |
| 离开热点 | 解除热点额度限制；当天用量保留 |
| 新应用 | 自动出现并标注「未设置上限」，不假装它已受额度保护 |
| 额度调整 | 不修改已用量；扩大额度可恢复新连接，减少额度可立即触发阻断 |
| 保留数据 | 保存应用规则和当前日汇总，不建设历史查询功能；跨日清理过期汇总 |

本机时钟、时区或联网路径变化后重新核对日期，不通过反复重启清零。第一版不做对抗管理员篡改时钟或数据库的防作弊系统。

## 4. 计量与阻断口径

macOS 主路线是 NetworkExtension 的 NEFilterDataProvider。按来源应用身份建立连接索引，持续处理受控连接的数据块，按 offset 去重并累计字节。多个进程、多个连接共用一个应用的额度账本。

Windows 主路线是 Windows Filtering Platform（WFP）：在 ALE 层捕获应用／用户／连接身份与建立连接的授权判定，在 TCP stream 和 UDP datagram 等对应层使用 C/C++ callout 驱动按流计量及阻断。具体层选择、流上下文和网卡绑定需要技术样机验证，不能直接套用 macOS offset 口径。C# 服务负责策略与持久化，驱动只承担必要的数据面职责。仅有定时轮询网速或添加用户态防火墙规则，不作为已经实现长连接实时额度保护的证明。

额度判定在扩展内执行，界面每秒刷新与否不影响阻断。不能只依赖连接关闭时的报表；不能对需要后续计量的连接返回永久放行后就停止跟踪。使用分块放行判定，并在超额时 drop 后续数据／新流。

避免把界面、每个连接、每个辅助进程各自持有的剩余额度当成唯一真相。扩展内按应用串行或原子扣减，防止 98 个并发下载同时穿透同一额度。IPC 只传应用标识、计数字段、规则版本和状态事件，不传内容载荷。

为避免崩溃后重新发放已用预算，本地服务与扩展使用有界的小额预算预留／租约或等价持久化水位方案：先持久化发放量，再允许扩展消费。正常回报按实际消耗结算；异常中断时保守保留未结算部分。实现前验证吞吐、磁盘写入量和最坏的保守多计值，不对每个网络包同步写数据库。

应用数据口径不等于运营商计费：已进入手机／电脑的数据无法撤回，传输协议开销、重传、在途数据可能使运营商用量超过设定值。尤其 UDP 远端可能在本机丢弃后仍继续发包。界面应说明这是应用额度保护，不承诺字节级计费硬封顶；发布时给出实测的保护延迟和尾部流量。需要保护余量时，应明确展示产品口径，不能静默伪造用量。

## 5. 热点与代理

- macOS：NWPathMonitor + Network.framework 的 isExpensive 作为自动判断信号，不把所有 Wi-Fi 都当热点。
- Windows：Network List Manager／INetworkCostManager 与网络配置变更通知读取计量连接信号，结合本地连接标识与用户手动标记。计量连接不等于手机热点；不能仅靠 cost 标志就声称已识别手机或运营商网络。
- 用户可以将当前连接明确标记为热点；保留足够的本地连接标识，避免将 USB 网卡名称或动态 IP 当成永久热点身份。SSID 不是必需信息，不为显示网络名称强制请求定位权限。
- Wi-Fi 热点、iPhone USB 共享、切换网络以及已有长连接都必须真机验证。
- 额度控制需要关注流实际使用的接口；不能只看菜单栏主进程的默认路由。多网卡／分流／VPN 路由归属不明确时显示覆盖限制。
- 必测直连、Clash 系统代理、Clash TUN 与长连接。验证原应用归因、循环本地代理流、代理出口流之间的去重。
- 若某种代理模式无法可靠归因或阻断，不能显示完整支持，更不能把全部代理流量分摊给任意应用。该模式是发布前技术验证关卡，必要时调整采集／控制架构。

## 6. 技术栈与进程职责

采用双端原生路线：共用需求、额度语义、数据结构说明和测试用例；Swift 与 C# 分别实现本地规则。V1 不强制引入跨语言共享核心或 Web 界面框架。

### 6.1 macOS 技术栈

| 层级 | 技术 | 职责 |
| --- | --- | --- |
| 开发工具 | Xcode、Swift 6，具体版本按稳定工具链锁定 | 构建、签名、调试、测试 |
| 原生界面 | SwiftUI、MenuBarExtra(.window)，必要处 AppKit、NSWorkspace、SF Symbols | 菜单栏、弹出面板、图标、设置 |
| 保护服务 | Swift 本地 LaunchAgent，通过 SMAppService 注册 | 路径状态、SQLite 单写入、通知调度、规则管理、重连恢复 |
| 网络扩展 | NetworkExtension、NEFilterDataProvider，打包为 System Extension | 应用识别、分块计量、额度扣减、阻断 |
| 热点检测 | Network.framework、NWPathMonitor；必要时 SystemConfiguration 补充本地接口信息 | 自动信号＋手动标记、切网事件 |
| 本地通信 | 经签名身份验证的 NSXPCConnection | UI↔Agent↔Extension 的规则、计数与状态通信；断线重连 |
| 存储 | SQLite3 系统库，单写入队列／Swift actor；UserDefaults 存纯界面偏好 | 额度规则、当前日用量、去重状态、持久化水位 |
| 通知 | UserNotifications，UNUserNotificationCenter | 预警与超额本地通知 |
| 开机启动 | ServiceManagement、SMAppService | 注册后台服务和用户选择的登录启动 |
| 交付 | Developer ID、必要 entitlements、Hardened Runtime、Apple 公证 | 直接分发签名应用、系统扩展首次授权 |
| 验证 | XCTest／Swift Testing、XCUITest、受控 TCP／UDP 流量发生器 | 单元规则、原生交互、计量和阻断真机测试 |

建议三个可执行目标：MenuBarApp、ProtectionAgent、TrafficFilterExtension；另设 Shared Swift Package 共享模型、字节换算、规则状态机和 IPC 协议。

保护服务单独承担持久化、日期切换、通知与重连，避免面板关闭／UI 重建影响计量。扩展保持最小数据面职责；其沙箱和通信能力须按 macOS 实际签名配置验证，不假设它能任意写 App Group、发网络请求或上传内容。

主程序异常退出不主动清零，也不重复发放额度。热点保护状态已明确时，如额度账本或 IPC 状态不可信，优先暂停有额度规则的应用，并提供可恢复的异常状态；不能对整台电脑无提示永久断网。恢复流程、重连和普通网络释放需覆盖测试。

建议目标：TrayApp、ProtectionService、TrafficFilterDriver、Installer；共享 C# Contracts／Policy 库用于 UI 和服务的类型与协议。内核驱动保持小型、可审核，避免在网络回调中执行数据库或 UI 工作。

Windows 首发按单用户日常桌面场景验收，但归因、IPC 和账本仍必须绑定 Windows 用户 SID，不能将其他本机用户的流量误记到当前用户。共享系统服务独立分类，多用户同时登录的冲突策略不默认为「最后一个托盘客户端说了算」。

### 6.3 双平台的共同约束

- 两端规则一致、各自在本机运行；Windows 和 Mac 不共享当日额度，也不进行云同步。
- 第三方框架即使能共享界面，也不能自动替代 macOS Network Extension 或 Windows WFP 引擎。选择原生路线是本项目取舍，目的是把精力集中于额度保护、后台可靠性和安装交付。
- 两端都要完成代理／VPN、TCP／UDP、IPv4／IPv6、网卡切换、服务异常、日界切换、重启恢复与安装卸载验证。
- V1 不承诺完全相同的 API 字节口径；需要给出一致的产品解释和两端各自的实测误差。

## 7. 本地数据与隐私

仅保存 appKey（签名身份／来源身份）、显示名、规则（上限与阈值）、当前日上下行字节、通知状态、规则版本和预算水位。应用身份不能单用 PID，避免进程重启导致重新获得额度。

macOS 数据放在应用专用的本地 Application Support 或经权限设计的本地共享容器；Windows 服务账本放在专用 ProgramData 子目录，按服务身份、管理员和所需客户端能力设置 ACL，按用户 SID 隔离数据，界面偏好留在用户 LocalAppData。两端都不主动放入云盘，不使用 CloudKit。IPC 需验证调用方身份和允许操作，不仅依赖可猜测的端点名称。不采集网址、聊天正文、文件内容或登录凭据，不建立遥测／广告／自动更新网络通路。

「不上传」指本产品不传输这些信息；用户自行开启的系统备份、诊断和原有应用的正常联网属于独立系统行为，不能宣传为本产品能禁止的行为。

## 8. 实施顺序与验收

1. 两端技术样机：macOS 扩展及 Windows WFP 服务／驱动分别启动；正确归因一个 TCP／UDP 应用；小额度下验证持续计量、预警、已有连接阻断和重连仍被阻断。先验证核心能力，再完成各端界面。开发期测试签名与正式发布签名明确区分。
2. 热点与代理：Wi-Fi、USB、切网、系统服务、Clash 两种模式；核对误计和重计。
3. 后台可靠性：IPC 身份校验与重连、并发额度、重启恢复、持久化、跨日、睡眠唤醒。
4. 菜单栏／托盘交互：两端主面板、单应用额度编辑、必要设置、通知、首次授权和退出语义。
5. 发布验证：真实 DMG／EXE 安装、权限拒绝、升级回滚、修复与卸载停用、断电恢复、高吞吐性能、长时间运行；macOS 签名公证、Windows 应用与驱动签名、隐私网络审计。

验收必须报告：计量误差、额度判定延迟、触发后的尾部流量、CPU／内存开销、异常恢复行为，以及代理模式支持范围。不要事先编造尚未测量的上限。

## 9. 安装包与正式应用交付

### 9.1 macOS：DMG

- 交付名示例：`FlowQuota-<version>-universal.dmg`。若无法在所有组件实现 Universal 2，则发布 `-arm64.dmg` 与 `-x64.dmg`，下载入口明确架构。
- DMG 内含正式 `.app` 和 Applications 拖拽入口；用户复制到 Applications 后启动。DMG 只是分发容器，不意味着所有后台组件已经安装启用。
- 首次启动再引导系统扩展与网络过滤授权；组件就绪后才能显示「保护中」。
- 对应用、嵌入组件和分发产物执行适用的 Developer ID 签名、公证及票据装订，测试下载隔离属性和干净系统安装流程。
- 提供本地「卸载保护组件」流程，先停用过滤、注销服务和扩展，再指导删除应用；数据保留与删除由用户选择。

### 9.2 Windows：EXE 为用户入口，MSI 为内部安装载荷

- 交付名示例：`FlowQuota-<version>-windows-x64-setup.exe`。安装器内部可携带 `.msi`；MSI 独立分发可作为后续企业部署选项，不增加第一版普通用户的选择负担。
- 使用完整离线安装包，包含应用、所需 .NET 运行时／依赖、后台服务、驱动和卸载组件；不得在热点上静默下载 GB 级依赖。采用自包含 .NET 发布时不另要求用户安装 .NET。
- 安装器通过 UAC 获取必要权限，驱动载入可能需要重启；明确展示是否需要重启，在驱动正常工作前保持「未就绪」。日常 UI 不要求一直管理员运行。
- 正式版按目标 Windows 版本完成驱动签名提交、认证／验证要求，检查 Secure Boot、内存完整性等目标安全配置；不能要求用户关闭系统安全机制或开启测试模式才能使用正式版。
- 支持 Windows 已安装应用中的卸载、安装失败回滚、版本升级、服务修复；升级期间避免无提示放行或遗留永久断网。清理本产品注册的 WFP filters／callouts／provider、服务和驱动，保留系统与其他产品的防火墙规则。
- 驱动发布资格、证书、Microsoft 签名流程与时间是发布依赖，不能把「EXE 已打包」视为 Windows 保护能力已交付。

## 接口总量与应用分析更新（2026-11-05）

顶部总量独立读取可确定的单一物理计量接口收发字节差，应用列表继续归因分析，二者不互相替代。接口总量按日写入 schema v3 的独立汇总表，不把旧应用行合计回填。应用阈值提醒保留原有语义。

网络不可确定、VPN/多网卡候选不明确时，总量显示不可用或已有保存总量及间断原因，不将虚拟接口和物理接口合计。初次基线、切网、跨日、休眠/重启、读失败及计数回退后的未知增量均不回填。接口采样与 nettop 归因各自每2秒运行，归因失败不应停止接口总量采样。

验证限制：本轮不得用热点进行下载、上传、测速或对照实验。使用模拟计数、系统调用注入和临时数据库验证；编译及签名通过不表示运营商误差已验收。顶部不是运营商扣费，仍可能包含局域网及协议层额外字节。


## 后台大流量预警范围更新（2026-11-05）

用户批准新增接口每日总量、接口短时和每个应用／服务短时预警。schema v4 保存全局配置及当天事件，事件兼作待发队列，不存跨日历史报表。默认每日接口 1 GB，默认最多 3 分钟接口／每个应用分别 200 MB（已保存配置不覆盖），短时同来源冷却 10 分钟；全部可独立关闭，保留原应用每日提醒规则。接口检查不依赖应用归因；友好分类不能把共享下载服务擅自认定为壁纸或某个请求应用。设置、窗口重建、通知、容量与无热点验证边界见 `traffic-alerts.md`。此更新覆盖早期关于设置仅有基础开关、提醒只按应用和不保存事件的范围说明；不扩展阻断功能。


## 双网络类别需求更新（2026-11-05，已接入 schema v5）

用户要求热点类和普通 Wi-Fi 类都统计，但用量与提醒必须分开。此节覆盖早期普通网络不累计及仅有一套提醒账本的范围；服务、SQLite 分类账本、提醒及界面均按此分类，验证记录见 implementation-status.md。

| 计量类别 | 网络来源 | 统计 | 新配置提醒默认值 |
| --- | --- | --- | --- |
| 热点／高成本网络 | 系统高成本路径或手动标记的热点 | 采集开启时累计 | 开启 |
| 普通网络 | 可用且未归入热点／高成本类的网络，包含普通 Wi-Fi、有线网络 | 采集开启时累计 | 关闭，可独立开启 |

- 保留系统识别来源：系统高成本信号不能展示为已经确认的手机热点。未知或不可用路径不分配新增流量。
- 两类各自拥有接口每日总量、应用每日用量、应用每日提醒规则，以及接口每日、接口短时、应用／服务短时预警配置。提醒的判定、通知去重、冷却与记录必须带有类别，普通网络流量不能触发热点类提醒。
- 默认值只用于新类别初始化。升级保留已有用户阈值、开关及窗口设置；新建普通网络类所有提醒默认关闭，包括应用每日提醒。默认开启提醒仍受系统通知授权约束，不表示已获授权。
- 界面可分别查看两类的总量、应用明细和提醒设置；明确显示当前连接归属，避免将两个类别合成一个未标注的“今日用量”。
- 手动热点仅修正当前连接的归类。关闭后普通网络仍统计；切网或切换标记时重建采样基线，已记录流量保留原类别，不搬移、不回填不确定区间。
- 已有账本是在热点／高成本范围内产生的，升级时保留在该类。普通网络无旧观测数据，从功能启用后的有效基线开始累计；不把未统计期间展示为完整自然日的零用量。
- 类别、复合键、索引、事务及版本化迁移设计见 database-design.md 的 schema v5 章节，保证两类持久化隔离。仍只保留当前日汇总及有界预警事件，不扩展采样流水或跨日历史。
- 验证使用模拟计数和临时数据库，重点覆盖类别切换、提醒独立、重启、跨日及旧数据迁移；禁止产生热点实验流量。

## 2026-11-06 留存范围更新

提醒版的统计及事件严格只保存当前自然日，跨日清理包含旧版未结算租约，不再以历史安全证据为由留存；日期回退同样清理非当前日。规则和设置保留。后台每 30 秒检查日期，暂停采集不暂停清理，服务停止或电脑休眠期间的清理在恢复后执行。SQLite 清除删除单元并截断旧 WAL。开发备份、诊断副本和旧安装版本本次单独清理，不新增流量备份。未来阻断账本需重新验收。
