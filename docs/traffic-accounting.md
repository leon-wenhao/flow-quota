# 流量总量与应用来源

更新：2026-11-06。本文是当前提醒版的计算与展示口径；替代旧说明中“只显示识别成功的来源／隐藏代理内核／应用归因合计作为主图总量”的规则。

## 总量不能因来源未知而减少

Mac 总流量来自可明确选择的一个物理接口的 64 位上传、下载计数增量。当前网络类别、自然日、采样连续性各自隔离；不能把应用合计当作接口总量，不能累加物理与虚拟接口。菜单栏、应用列表概览、主图和接口预警始终使用这套独立计数。

主图按用户所选范围汇总既有接口分钟记录。没有分钟记录表示未知；有正样本数、字节为零表示观测零。应用查询失败、API 不可用、来源容量不足时，接口总量仍展示。暂停、重启、跨日、切网或间断后的基线不补量。因此“完整”指全部有效观测字节，没有承诺服务未运行时的流量或运营商账单精度。接口包含局域网通信、协议开销，不覆盖手机本身或其他设备。

## 应用／进程必须保留

nettop 的应用及系统服务记录按完整身份展示，代理内核不再过滤，低排名记录不再只保留前十名。`verge-mihomo` 显示为“Clash 代理内核（来源应用待确认）”；这表示已知传输进程，但尚未完全确认请求它的原始应用。其他共享服务也保留身份及用途未确认的说明。

Clash API 识别到的应用或固定站点是代理内的辅助线索，独立分组，不与代理内核或其他进程再次相加，不进入 nettop 数据库、应用额度或接口总量。它们包含 DIRECT 规则，不能称为必经代理节点的流量。连接生灭、首帧、故障及重启可能导致线索缺失；不能按当前连接倒推过去用途，也不能宣称 Logi Options+ 的已识别部分解释了所有代理字节。

进程用量及 Clash 辅助明细分别滚动查看；主图悬停先列接口总量，再列进程线索。悬停摘要超出空间时明确给出总项数和完整明细入口，不悄悄删除数据。接口主图不把不同来源强行堆叠成精确分摊；进程双饼图标明“进程观测比例（非 Mac 总量分摊）”，不把不完整或重叠证据冒充总量的份额。

## 未识别／计量差额

分别对上传与下载比较接口观测 `T` 和同范围进程观测合计 `P`：

- 任一侧未观测／无效：来源对应未知，不显示为零，不替换已知总量。
- `T > P`：显示“未识别／计量差额 T−P”，说明已经包含在总量内，可能包含未识别来源、协议开销或采样时间差。它不是一个被测得的“未知应用”，不创建身份、账本或提醒规则。
- `P > T`：显示超额 `P−T` 及重复观测／时段差异，保留所有原始数字；不裁剪、按比例缩放、删除进程或把差额取零后假称已经平账。
- `P == T`：数值相等也不能证明逐字节对应；上传／下载各自核对，避免一侧超额与另一侧缺失相互抵销。

现有接口、nettop 和 Mihomo API 是独立观测，无法为每个接口字节证明唯一的原始应用。不得承诺它们总能拼成精确的 100% 应用分摊。该能力未被本轮实现，也不能通过改文案、数学缩放或反推差额伪造。

## 预警与容量

接口每日及短时预警依据完整接口用量，独立于应用识别成败；应用每日及短时预警依据各自进程账本／窗口，不把接口差额或 Clash 子来源加到某个应用上。触发记录保留实际总量，展开显示已有进程证据（含代理）、缺失状态或计量差额。

查询行数、1 MiB IPC、Clash 来源及预警证据各有容量边界。超过边界必须说明来源覆盖不完整或查询失败，不能伪称完整；接口总量继续独立显示。允许缩短查询时段；不会提高采集内容范围或静默丢弃流量来使请求成功。

## 验证用例

使用合成数据重现报告中的量级：接口下载 790,343,680 bytes、上传 41,725,952 bytes，合计 832,069,632 bytes；代理进程 805,815,369 bytes；Clash 已识别下载仅 322,900,000 bytes。主图仍显示全部接口字节，代理记录保留，Clash 子来源不重复相加；进程／接口差额独立说明。

验证只使用模拟计数、临时数据库和原生视图渲染，不生成热点测试下载／上传，不修改本机统计数据库、不重启实际服务。未补认历史连接，未重新验证运营商误差及全部系统／VPN 组合。
