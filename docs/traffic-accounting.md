# 流量总量与应用来源

更新：2026-11-06。当前源码计算契约；取代早先“代理内核与辅助来源分列、日常页面常驻归因差额核对”的展示。详细方案见 [Clash 完整拆分](clash-usage-breakdown.md)。

## 独立保留 Mac 总量

Mac 今日及所选时段总量来自明确选择的单一物理接口的 64 位上传、下载增量。按当前日、网络类别和连续观测范围隔离，不能使用应用相加替代，不能叠加物理与虚拟接口。应用/API 识别、保存或查询失败不减掉接口量。空白为未观测，正样本零字节为观测零；启动、重启、切网、跨日与间断重建基线，不补量。

完整指服务有效观测字节，并非完整自然日或运营商账单。包含局域网和协议开销，不含手机本身及其他设备。接口与进程是独立观测，仍不能保证每个接口字节唯一对应到具体应用。

## 来源展示使用接口父项核对

日常列表、菜单栏前三、分时来源和上传／下载饼图使用“接口父项＋同分钟来源＋其他未识别”结果。每个有效接口分钟分别核对上传和下载：来源两方向都不超过接口父项时保留来源原数，并把差额显示为“其他未识别”；任一方向超出、来源冲突或数字无效时，该分钟接口父项全部归“其他未识别”，不截断、缩放或用其他分钟抵扣。没有接口父项的进程记录不能反造接口用量。

这层结果只负责完整流量的展示与来源分拆。原始应用账本仍保存 `nettop` 进程观测，用于应用每日规则和应用预警；原始值可能大于接口父项，必须在计量详情中保留并标明重叠／时间差，不能直接放进接口来源列表或当作接口总量。这样，截图中微信原始观测 22.5 MB 与接口 11.5 MB 冲突时，主列表显示接口父项核对后的“其他未识别”，微信 22.5 MB 留在原始进程详情，不会伪装成接口内的 22.5 MB。

## Clash 父项完整拆分

以精确识别的 nettop 内核为父项，在相同日期、类别及绝对分钟内读取 Mihomo 已识别站点/应用连续增量。逐方向检查已识别量不超过父项。可靠来源保留原数，余量全部显示为“其他未识别（Clash）”。例如内核下载 800MB、虎牙和 YouTube 各 300MB，则显示三个来源 300MB、300MB、200MB；父项不再次进入列表、排名、图例或来源合计。

任一方向超出、来源数字无效或身份冲突，则该分钟父项全部显示为未识别；不缩放、不裁剪、也不借其他分钟补足。原始证据留在计量详情。没有父项时不能以 API 子项反造父项。每日结果只接纳通过分钟核对的来源，旧日合计中缺少分钟证据的部分保留为未识别，不猜测补填。

这些计数不是同一逐包计量器，拆分是以父项为边界的来源展示，不承诺精准恢复全部网络用途。未知部分可能包括未捕获连接、首帧/重启缺口、未确认站点、协议及时间差。不能据此将浏览器日用量称为已扣除代理的直连量；其他应用继续保留原始进程观测。接口差额不伪装成实测未知应用。

## 共用展示与提醒

应用列表、菜单栏前三、时段表格、主图悬停和上传/下载饼图共用拆分结果；所有低排名来源可滚动查看。饼图是同一来源集的方向分布，不将它冒充物理接口的精确分摊。计数核对、原始内核与 API 证据集中到用量详情；日常页面不再反复显示归因核对段落。采样、存储、容量及查询异常仍直接提示。

接口预警依据独立接口总量；应用预警和每日提醒保留原来的 canonical 身份与原始用量。Clash 整体提醒在用量详情的内核入口编辑，子项不成为额度身份。新事件在触发时冻结来源子项，上传/下载各方向加总必须等于触发父项；短时事件仅接纳被触发窗口完整包含的单调时钟来源区间，交叉边界、未来和错误类别的来源不用。旧事件不拿当前数据回填。

## 留存、容量与验证

schema v9 保存当天来源分钟汇总，服务重启仍可读取；源表不存域名、IP、连接 ID 或网络内容，不写 nettop 日账本，不增加接口总量。每类别/当前日最多 128 个来源、32768 个来源分钟单元，批次事务失败会显示错误，未保存部分由父项的未识别余量保留。跨日、日期回退与其他统计一起清理，规则保留，secure_delete 与 WAL 截断沿用。

只用合成计数、临时 SQLite、通知替身及原生视图验证 800=300+300+200、方向冲突、分钟隔离、旧数据、重启、日期回退、容量和回滚。禁止生成下载、上传或热点实验流量。真实 VPN/TUN、运营商精度及原应用逐字节还原没有在本轮验收。
