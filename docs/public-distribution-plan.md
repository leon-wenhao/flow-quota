# 私有源码与公开安装包分发方案

用户于 2026-11-06 批准实施。此方案仅适用于 Flow Quota。

## 仓库边界

- `leon-wenhao/flow-quota`：保持私有，保存源码、开发文档、测试和构建脚本。
- `leon-wenhao/flow-quota-releases`：独立公开仓库，只保存 README、安装说明、分发说明、品牌图标及更新清单；Issues 用于反馈。应用为闭源分发，不称为源码开源。
- 公开仓库从空仓库建立，禁止由私有仓库修改可见性、镜像或推送源码历史。公开 tag 只指向公开仓库自身提交。
- 公共资料严格按文件白名单复制；二进制附件严格按发布清单上传。不得上传数据库、日志、调试符号、本机配置或私有提交标识。

## 发布顺序与验收

1. 修改客户端默认更新地址，指向公开仓库 `main/update-manifest.json`，保留用户主动检查和 DMG 手动安装。
2. 私有源码版本、Info.plist、根清单一致；版本用三段数字，build 递增。tag 使用 `v版本-build.构建号`，禁止覆盖正式版本。
3. 离线测试清单、大小、SHA-256、文件白名单及失败分支；执行 Swift 回归和双架构 release 构建，验证包内 app/Agent 签名、架构及最小系统版本。
4. 将公开资料推送到独立公开仓库，在公开仓库创建 tag 和 Release 草稿。仅上传两个 DMG、SHA256SUMS、两份 JSON 清单及发布说明。
5. 对照 GitHub 资产元数据核对文件名、大小和 SHA-256；成功后发布 Release，最后提交公开仓库的更新清单。失败时不激活清单；可用同一本地 bundle 恢复草稿。
6. 用仓库可见性、Release 和小清单核对线上结果，不为验收下载 DMG，也不生成热点实验流量。

源码提交与公开提交分开处理。发布脚本要求源码和公开资料均有可追踪提交；不会将公开清单推回私有仓库，不会替用户自动提交尚未审查的源码。

## 客户端与分发限制

- 首个包含新更新地址的版本，需要旧版用户手动安装一次；之后可主动检查公开清单。
- 当前包仅 ad-hoc 开发签名，未 Developer ID 签名或 Apple 公证，公开页必须明确此状态。遵循 Apple 针对单个应用的正常打开流程，不提供关闭系统安全功能的命令。
- Intel 包可在 Apple Silicon 上交叉编译、检查架构；未使用 Intel 真机时不声称已完成 Intel 运行验收。
- 软件仅统计和通知，不阻断网络。公开下载无法保证二进制不可逆向；仓库隔离保护的是源码和提交历史。
- 暂不引入 Actions、令牌同步或自动安装。以后跨仓库自动发布另行设计最小权限凭据。

## 维护入口

流程与恢复命令见 `docs/release-macos.md`。公开资料源位于 `distribution/public/`，公开提交通过官方 REST API 从白名单文件生成，不能使用源码仓库的 worktree 或提交历史。

实施时本机 Git 直连端点发生 HTTP/2 错误及连接超时；公开资料与清单改用 GitHub 官方 REST API 原子提交，仓库与文件边界保持不变。
