# 开源与单仓库发布方案

2026-11-06 用户批准执行。本方案替代此前“私有源码＋独立公开分发仓库”方案。

## 目标与决定

- `leon-wenhao/flow-quota` 改为公开，统一管理源码、文档、Issues、tag 和 Releases，使用 MIT 许可证。
- DMG 只作为 Release 附件；`.artifacts/` 继续忽略，不把二进制提交进 Git。
- 现阶段没有旧版使用者，无需旧更新入口、重定向或过渡期。新入口验收后删除 `leon-wenhao/flow-quota-releases`。
- 主动检查更新的语义不变；应用读取本仓库 latest Release 的 `update-manifest.json` 附件。版本仍采用三段版本号＋内部递增 build，唯一 tag 为 `v版本-build.构建号`。

## 执行顺序

1. 检查当前文件和全部 Git 历史：凭据、私钥、数据库、构建产物与内部资料；若发现真实敏感数据，先处理再公开，不用删除 HEAD 文件冒充历史已清理。
2. 更新 AGENTS、许可证、README、发布文档、更新地址及发布测试；移除跨仓库资料同步和独立历史检查。
3. 发布脚本只接受本源码仓库，要求已审查的干净源码、准确的远端 main 与 tag；构建双架构 DMG，记录源码提交，显式验证附件白名单及大小／SHA-256。
4. 将已验证提交推送本仓库，改为公开；现有 0.1.2 的 DMG 可原样迁入本项目归档，并注明其内置旧更新地址。新发布 0.1.3 使用新入口，不为旧版本提供兼容。
5. 创建正式版草稿，上传并核对附件后发布；核对正式附件后才标记 latest。失败可复用同一 bundle，不覆盖已正式发布附件、不回退 latest。
6. 只读核对公开仓库、源码 tag、下载链接和 latest 清单；随后删除旧分发仓库。缺少删除权限时明确报告，不能声称完成。

## 分支与发布维护

- `main` 保存可发布源码；日常修改使用 `codex/功能名` 分支并通过审查合入。
- tag 指向实际构建源码，不复用、不改写已发布 tag；重构建使用新 build。
- 本地根 `update-manifest.json` 是构建输入，latest Release 附件才是已验证的在线清单，避免先改版本号就让客户端发现尚未上传的包。
- 不新增 CI、额外服务器或自动升级任务；用户点击检查更新后下载并打开 DMG，仍由用户拖入 Applications 完成安装。

## 验收与限制

- Python 离线测试覆盖同仓库身份、源码 tag、草稿恢复、摘要校验、latest 激活顺序、版本回退和同版本变更拒绝。
- Swift 应用测试与双架构 release 构建、签名／架构／最小系统版本检查；不做热点流量实验、不为验收重新下载 DMG。
- 当前 ad-hoc、未公证和提醒版限制继续公开；未验证的 macOS 14、Intel 真机运行不声称通过。
- 迁移实际执行结果与权限限制记入 `docs/public-distribution-verification.md`。
